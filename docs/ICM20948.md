# ICM20948: DLPF и частоты

## Значение по умолчанию

`gyro_dlpf = AUTO`: для ICM20948 выбирается включённый DLPF (режим `188Hz`,
фактическая полоса gyro около 197 Гц). Для остальных IMU AUTO сохраняет
прежний выбор `256Hz`. Существующие сохранённые настройки не мигрируют:
обновление прошивки само по себе их не заменяет.

## CLI

Включить DLPF явно:

```text
set gyro_dlpf = 188Hz
get gyro_dlpf
save
```

Вернуть автоматический режим (на ICM20948 он тоже включает DLPF):

```text
set gyro_dlpf = AUTO
save
```

Выключить DLPF гироскопа:

```text
set gyro_dlpf = 256Hz
get gyro_dlpf
save
```

Используйте полные имена, включая `Hz`. Число `188` не является именем режима:
CLI может трактовать его как внутренний индекс. Второй режим bypass называется
`EXPERIMENTAL`, не `EX`.

После save плата перезапускается. Проверка: `get gyro_dlpf`, `stats`, `devinfo`.

## Частоты

| Режим gyro | ODR датчика | Опрос P4 I2C | Опрос P4 SPI |
| --- | --- | --- | --- |
| AUTO / 188Hz (DLPF ON) | 1125 Гц при делителе 0 | 1125 Гц | 1125 Гц |
| 256Hz / EXPERIMENTAL (DLPF OFF) | 9000 Гц | 1800 Гц | 3000 Гц |

Частота PID дополнительно зависит от loopSync. Частота шины не равна ODR:
I2C не выше 400 кГц, SPI: настройка 1 МГц, чтение с запросом 7 МГц.
Фактический SPI SCK округляется аппаратурой. Accel настроен отдельно, с DLPF
и ODR 1125 Гц; режим bypass gyro не отключает DLPF accel.

Имена полос исторически MPU-совместимые. Остальные режимы `98Hz`, `42Hz`,
`20Hz`, `10Hz`, `5Hz` также включают DLPF с ближайшей полосой ICM20948.

## Можно ли фильтровать программно?

Да: XSFC уже применяет программные фильтры gyro. Отключение аппаратного DLPF
не отключает программную фильтрацию и позволяет уменьшить аппаратную задержку.
Но это не равноценная замена при произвольной частоте опроса:

- Данные, пропущенные между чтениями, программным фильтром не восстановить.
- При чтении 9000-Гц потока на 1800/3000 Гц высокочастотный шум может попасть
  в полезную полосу (алиасинг) до программной фильтрации. Последующий low-pass
  уже не отделит его от настоящего движения.
- Для качественной программной децимации нужен захват исходного потока через
  DRDY/FIFO, фильтрация до снижения частоты и проверка вычислительного бюджета.

Для текущего таймерного опроса, особенно I2C, AUTO с DLPF — более осторожное
значение по умолчанию. Bypass остаётся доступен для проверок на SPI.
Проверять шум, задержки и стабильность нужно без пропеллеров; не переносить
непроверенные настройки сразу в полёт. Коэффициенты PID автоматически не меняются.
