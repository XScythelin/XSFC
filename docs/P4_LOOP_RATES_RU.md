# ESP32-P4: настройка gyro, PID и миксера на 2 / 4 / 8 кГц

Инструкция для XSFC ESP32-P4 с ICM42688 по SPI. На ESP32/S3 и I2C
действуют другие ограничения; эти примеры не гарантируют там 8 кГц.
Проверенная полётная база — 2/2/2 кГц. Выбор 4 и 8 кГц сохранён, но это
не означает, что режимы 4/4/4 и 8/8/8 прошли полётную проверку.

## Перед изменениями

1. Снять пропеллеры, оставить аппарат disarmed, подключить USB.
2. Закрыть другие программы, использующие COM-порт. Открыть CLI конфигуратора.
3. Выполнить `dump all` и сохранить вывод в файл для отката.
4. Менять только приведённые параметры частоты. Не выполнять `defaults`,
   сброс калибровок или стирание флеша. PID, trims, пины и фильтры сохраняются.

## Как связаны частоты

- `gyro_rate` — запрошенная частота чтения gyro: 2000, 4000 или 8000 Гц.
- PID = фактическая частота gyro / `pid_sync`.
- Миксер = частота PID / `mixer_sync`.
- Делители должны быть целыми положительными. PID не быстрее gyro,
  миксер не быстрее PID.
- Внутренний ODR ICM42688 остаётся 8 кГц; это не то же самое, что частота
  чтения gyro хостом. Accel и fusion остаются около 500 Гц во всех трёх режимах.

## Готовые команды

Вставлять **один выбранный блок**, а не все подряд. `save` сохраняет настройки
и перезапускает контроллер; после перезапуска подключиться снова.

### 2 кГц: gyro / PID / миксер = 2000 / 2000 / 2000 Гц

```text
set gyro_rate 2000
set pid_sync 1
set mixer_sync 1
save
```

Это проверенная базовая настройка и способ возврата после эксперимента.

### 4 кГц: gyro / PID / миксер = 4000 / 4000 / 4000 Гц

```text
set gyro_rate 4000
set pid_sync 1
set mixer_sync 1
save
```

### 8 кГц: gyro / PID / миксер = 8000 / 8000 / 8000 Гц

```text
set gyro_rate 8000
set pid_sync 1
set mixer_sync 1
save
```

### Смешанные режимы

| Gyro, Гц | PID, Гц | Миксер, Гц | gyro_rate | pid_sync | mixer_sync |
|---:|---:|---:|---:|---:|---:|
| 8000 | 4000 | 4000 | 8000 | 2 | 1 |
| 8000 | 2000 | 2000 | 8000 | 4 | 1 |
| 4000 | 4000 | 2000 | 4000 | 1 | 2 |

Для смешанного режима задать три значения из строки через `set`, затем `save`.

## Проверка после перезапуска

Выполнить `stats`: проверить `gyro rate`, `loop rate` (PID), `mixer rate`
и фактические частоты секций. `gyro clock: 8000 Hz` — внутренние часы датчика,
а не подтверждение работы PID на 8 кГц. Выполнить `dump all` для проверки
сохранённых `gyro_rate`, `pid_sync`, `mixer_sync` и параметров Blackbox.

На высоких частотах проверить нагрузку и стабильность сначала без пропеллеров.
Показания Work time включают ожидание периферии и не равны чистой загрузке CPU.
Поддержка делителей не гарантирует соблюдение каждого дедлайна под нагрузкой.
Если фактическая частота ниже заданной, появляются сбои или пропуски логов,
вернуться к 2 кГц и исследовать причину, а не увеличивать частоту дальше.

## ESC и Blackbox

- Примеры для высоких частот подразумевают подходящий DShot и совместимые ESC.
  Не менять протокол, DShot telemetry или оборотные фильтры автоматически.
  PWM/Oneshot имеют отдельные ограничения частоты; для них эти таблицы
  не являются обещанием частоты выхода. Частота миксера также не доказывает,
  что каждый ESC-пакет физически отправлен с той же частотой.
- Blackbox оставлять включённым: `blackbox_dev FLASH`,
  `blackbox_flash_mode PSRAM`, штатный `debug_mode NONE`.
- При необходимости восстановить эти три параметра через `set` и `save`.
  Не включать диагностические режимы без конкретной задачи.
- `blackbox_rate` этими блоками не меняется. При смене PID частота записи
  может измениться: проверить заголовок/интервалы полученного лога.
  На 8 кГц полная запись быстрее расходует PSRAM и повышает нагрузку.
- После disarm дождаться успешного завершения сохранения лога
  (сигнал окончания BEEP1 → BEEP2 → BEEP3), только затем отключать питание.
  При незавершённом/ошибочном сохранении не обходить ARM-interlock.

`config/p4_2khz_baseline.cli` — отдельный более широкий набор PID/фильтров.
Для простой смены частоты он **не нужен**: его импорт изменит и другие параметры.
Сохранение также фиксирует текущий gyro bias в gyro offsets штатным `preSave`;
это не команда новой accel-калибровки.

Известные ограничения: причина редкого повреждения памяти и периодического
ухода горизонта под нагрузкой окончательно не установлена. Смена частоты сама
по себе не считается исправлением этих проблем.
